# /yt-sintese — Synthesis of yt-nota drafts

**Always respond in Brazilian Portuguese (PT-BR). Notes written to the vault are always PT-BR (the user's second brain in their native language). Only agent instructions in English.**

You synthesize drafts generated by the `yt-nota` CLI into complete Obsidian notes in the user's vault.

## Where everything lives

The paths below use placeholders. Replace with the real paths of your setup (recommended: define in `yt-nota`'s `.env` via `YT_NOTA_VAULT`).

- **Vault:** `<vault>` (e.g., `~/Documents/Obsidian` or equivalent path on your OS)
- **Pending drafts:** `<vault>/30-Recursos/Literatura/Pipeline/_processar/*.draft.md`
- **CLI:** `yt-nota` (installed via `pip install -e .` in the `yt-nota` repo)
- **Final notes:** `<vault>/30-Recursos/Literatura/<dominio>/<Canal>/3-<id>-<slug>.md` (domain resolved via `config/channel_domains.yaml`; valid domains come from the configurable taxonomy in `config/domains.yaml`, see `config/domains.example.yaml`)
- **Channel cards:** `<vault>/30-Recursos/Notas/Cards-de-Pessoa/<Canal>.md`

## Flow

### Step 1 — List drafts

```bash
yt-nota --list
```

If it returns "Sem drafts pendentes": stop and report that there is nothing to synthesize.

### Step 2 — For each draft (in parallel where possible)

**(a) Read the draft:** use the Read tool on the draft path.

Draft structure:
- Frontmatter with `titulo`, `canal`, `canal_url`, `data_publicacao`, `duracao`, `url`, `idioma_transcript`, `transcript_origem`, `tags_canal`, `tema` (optional)
- `## Descrição do vídeo` section
- `## Transcript` section with `[mm:ss] texto` lines

Possible values for `transcript_origem`:
- `manual` — official creator captions (most reliable)
- `auto` — YouTube auto-caption (variable quality, especially in PT-BR)
- `whisper-local` — locally transcribed via faster-whisper (yt-nota v0.3.0+, triggered when YouTube returns 429). Good quality in PT-BR but may miss exotic technical terms. When this is the value, slightly weight the video description more in "O que defende" if any transcript excerpt looks strange.

**(b) Generate the synthesis body** (only the 7 sections below) following ALL style rules of this skill.

**(c) Write the body to a temporary file** with Write at a path like:
```
<tmp-dir>/tmp_body_<draft_id>.md
```

**(d) Call finalize:**
```bash
yt-nota --finalize "<path_do_draft>" --body-file "<path_temp_body>"
```

**(e) Clean up:** delete the temp body file after successful finalize (no need to delete the draft — finalize handles that).

### Step 3 — Report

Summarize what was done: how many notes generated, vault-relative paths, any failures.

## Style rules (NON-NEGOTIABLE)

- **PT-BR** always
- **No em dash** "—". Use period, comma, colon
- Personal tone, not formal
- No profanity
- No AI markers: "Vamos explorar", "Esse vídeo traz", "É interessante notar", "Em suma", "Em resumo", "Por fim"
- Quotes in blockquote `>`
- Straight to the point. Zero fluff.

## Body structure (synthesis output)

You produce EXACTLY these 7 sections, in order, with `---` separators. **Nothing before the first section. Nothing after the last.**

Each section follows a **depth + readability** pattern: short paragraphs (max 3-5 lines), liberal use of `###` sub-headers, bullets for values and examples, tables for numeric comparison. The reader scans fast AND deepens when needed.

```markdown
## Em uma frase

{Tese central em UMA frase clara. Não parágrafo. Pode ter vírgulas, mas é UMA proposição.}

---

## O que defende

**1. {Título do ponto: substantivo + verbo curto}**

{Abertura: 2-3 linhas que estabelecem o argumento.}

{Quando o ponto for multifacetado, quebra com sub-headers ou bullets:}

- **Aspecto A:** explicação curta com valor/exemplo concreto do vídeo
- **Aspecto B:** outro aspecto com dado
- **Aspecto C:** etc

{Fechamento opcional: 1-2 linhas conectando os aspectos.}

**2. {Segundo ponto}**

{Mesma estrutura. Use tabela quando há comparação numérica:}

| Item | Valor A | Valor B |
|---|---|---|
| ... | ... | ... |

{Comentário pós-tabela.}

**3. {Terceiro ponto}**

{Pra pontos longos com vários sub-temas, use `###` em vez de bold:}

### Sub-tema 1
{2-3 linhas}

### Sub-tema 2
{2-3 linhas}

(3 a 5 pontos. Cada um substancial: 8-20 linhas no total. Concreto, com exemplos literais do vídeo. Sem fluff.)

---

## O que mais me marcou

> *"{Citação literal mais impactante do transcript}"* `[mm:ss]`

{2-3 linhas: por que marca + conexão com a tese central do vídeo.}

{Se houver uma segunda citação importante em momento diferente:}

> *"{Segunda citação opcional}"* `[mm:ss]`

{1-2 linhas comentando.}

---

## O que isso muda pra mim

{Abre com a aplicação principal em 2-3 linhas.}

{Quebra em sub-aplicações quando faz sentido:}

- **Pra {projeto X}:** aplicação específica em 1-2 linhas
- **Pra {projeto Y}:** outra aplicação
- **Pra {projeto Z}:** etc

{Invoque projetos do usuário (configurados no próprio contexto da sessão Claude Code, via CLAUDE.md ou conversa).}

{Fecha com 1 linha de decisão ou próximo passo.}

## Dicionário

Cada entrada tem: **termo**, definição, valor/dado se aplicável, analogia ou aplicação:

- **{Termo 1}:** {definição funcional, 1-2 linhas}. **Valor de referência:** {número/range se mencionado no vídeo}. {Analogia ou contexto de uso.}
- **{Termo 2}:** {...}
- **{Termo 3}:** {...}

(5 a 8 termos técnicos relevantes, em ordem de aparição. Privilegia conceitos sobre nomes próprios. Sempre que houver número no vídeo associado ao termo, preserva ele aqui.)
```

## Notes for writing well

### Density rules (important)

- **Short paragraph.** Max 3-5 lines. If longer, break into bullets or sub-headers.
- **Use tables for numeric comparison.** Before/after, option A vs B, technical values side by side. A table reads better than 2 paragraphs.
- **Use bullets to list values, examples, brands, counterpoints.** Do not run them inline.
- **Use `###` (heading 3) inside complex points.** Sub-themes with `###` break visually.
- **Whenever there is a number in the video, preserve it literally.** Temperature, price, percentage, speed, equipment model. Those numbers serve as a practical recipe.
- **Cite the video explicitly when giving a concrete example.** "Ele mostra no vídeo um caso onde..." is better than abstract paraphrase.

### Per section

- **Em uma frase:** ONE sentence. May have commas, but one proposition. Not a paragraph.
- **O que defende:** 3-5 points. Each one substantial (8-20 lines total counting sub-bullets/tables). Each point starts with `**N. Title**`, sub-themes use `###` or bullets. Concrete, with numbers and examples from the video.
- **O que mais me marcou:** literal quote + `[mm:ss]` timestamp (timestamp comes from transcript). 2-3 lines of comment. If there is a second memorable quote at a very different moment, can include.
- **O que isso muda:** authorial part. Open with main application, then bullets per user project that connects. Close with decision/next step.
- **Dicionário:** 5-8 terms. Each entry: definition + reference value + analogy/application. Always preserve literal numbers.
- **Notas permanentes:** 2-4 titles. Declarative phrases that would sustain their own note.
- **Referência:** `CHANNEL-NAME. **Title**. YouTube, DD/MM/YYYY. URL.` (DD/MM/YYYY from data_publicacao of the draft.)

## Special cases

- **Transcript unavailable:** Use only description + title + tags. In "Em uma frase", mark with "(síntese a partir da descrição, sem transcript)". In "O que mais me marcou", if there is no concrete description quote, write: "Sem transcript disponível para citação direta."
- **Transcript in foreign language:** Quote translated excerpts into PT-BR in "O que mais me marcou", preserving meaning.
- **Short/shallow video:** 3 points in "O que defende" is the minimum. If there is really no substance, make the 3 points short and honest about the little there is.

## Preservation of technical configurations (IMPORTANT RULE)

If the video teaches **numeric configuration values** (temperature in °C, speed in mm/s, flow in %, pressure advance, layer height in mm, retraction in mm, infill %, wall count, top/bottom layers, etc), you MUST preserve the EXACT numbers in the synthesis. These data serve as a practical recipe to consult later.

**Where to put them:**

1. **Inside "O que defende":** if the configuration is the main point of one item, include the literal value in the paragraph. Example:
   > **2. Temperatura ideal varia por filamento**
   > Pra PLA, 200-210°C no hotend e 60°C na mesa. Pra PETG, 230-240°C no hotend e 80°C na mesa.

2. **In the Dicionário** (preferred format for recipes/cheat-sheet), use bullets with embedded value:
   > - **Pressure Advance (PA):** ajuste que compensa o atraso de pressão do filamento. Começa em 0.020, sobe pra 0.040 se ver under-extrusion nos cantos.
   > - **Flow:** taxa de extrusão. Default 100%, mas calibrado pode ficar 95-105% dependendo do filamento.

**What NOT to do:**

- "ajuste a temperatura adequadamente"
- "use a velocidade certa"
- "configure o pressure advance"
- Rounding numbers ("usa em torno de 200°C" when the video said "210°C")

**What to do:**

- "210°C pra PLA, 240°C pra PETG"
- "velocidade externa 30 mm/s, interna 80 mm/s"
- "pressure advance 0.020"
- If the video gives a range, keep the range: "200-215°C"
- If the video mentions brand/context of the config, preserve

The rule applies to ANYTHING replicable in the future: filaments (brand + conditions), tested printer models, slicers (with version), model sites/links. When in doubt, **preserve the literal value**.

## Anti-scope

- **Do not write frontmatter in the body.** The yt-nota finalize handles it.
- **Do not write the `# title` or the `> [!info]` callout in the body.** The finalize handles it.
- **Do not invent content not in the transcript/description.** If something is uncertain, omit or mark "(o vídeo não detalha)".
- **Do not cite the user's personal data (employers, salaries, financial data, health data, etc) — not as example, not as connection.** The rule is general, no exceptions.
- **Do not use malformed multi-line bash.** Each command should be on one line or use `\` continuation carefully.
